# 도메인 + HTTPS 로 전환하기 (비용 0원)

`http://<서버IP>:8000` 으로 쓰던 것을 `https://itam.우리회사.com` 처럼 바꿉니다.
**애플리케이션 코드는 그대로 두고** 아래 절차만 밟으면 됩니다. 전부 무료입니다.

전환하면 좋아지는 점

* 주소창에 자물쇠가 뜨고, 오가는 내용(비밀번호·자산 정보)이 암호화됩니다.
* IP 를 외우지 않아도 됩니다. 서버 IP 가 바뀌어도 주소는 그대로입니다.
* 브라우저가 카메라를 쓸 수 있게 되어, **사이트 안에서 QR 을 연속으로 스캔**하는 기능을
  넣을 수 있습니다. (HTTP 에서는 브라우저가 카메라를 막습니다)

---

## 1. 도메인 준비 — 둘 중 하나

### 방법 A. 회사 도메인이 이미 있다면 (권장)

`회사.co.kr` 같은 도메인이 있다면 **서브도메인 하나를 추가하는 것은 무료**입니다.
도메인을 관리하는 곳(가비아·후이즈·Cloudflare 등)에서 A 레코드를 추가합니다.

```
이름(호스트)   itam
유형           A
값             168.110.38.57      ← 서버 공인 IP
TTL            600
```

→ `itam.회사.co.kr` 로 접속하게 됩니다.

### 방법 B. 도메인이 없다면 — DuckDNS (무료)

[duckdns.org](https://www.duckdns.org) 에서 구글·깃허브 계정으로 로그인하면
원하는 이름과 토큰을 바로 받습니다. 비용도, 기간 제한도 없습니다.

1. 원하는 이름을 만듭니다. 예: `ourcompany` → 주소는 `ourcompany.duckdns.org`
2. 화면 위쪽의 **token** 값을 복사합니다.
3. 서버에서:

   ```bash
   ./deploy.sh duckdns ourcompany 복사한토큰
   ```

   주소가 이 서버를 가리키도록 맞추고, **5분마다 자동으로 확인**합니다.
   오라클 무료 VM 은 인스턴스를 껐다 켜면 공인 IP 가 바뀔 수 있는데,
   그때도 주소가 알아서 따라옵니다.

---

## 2. 오라클 콘솔에서 80 · 443 포트 열기

이 부분만은 오라클 웹 콘솔에서 직접 해야 합니다. (8000 번을 열었던 것과 같은 자리입니다)

```
네트워킹 > 가상 클라우드 네트워크 > 서브넷 클릭 > 보안 목록 클릭 > 수신 규칙 추가
  소스 유형   CIDR
  소스 CIDR   0.0.0.0/0
  IP 프로토콜 TCP
  대상 포트   80

같은 방법으로 443 도 추가
```

> 80 번은 인증서를 받고 갱신할 때 필요합니다(Let's Encrypt 가 이 포트로 확인합니다).
> 서버 안쪽 방화벽은 다음 단계에서 자동으로 열어 줍니다.

---

## 3. 전환하기 — 명령 한 줄

```bash
./deploy.sh https itam.회사.co.kr 담당자@회사.com
```

(DuckDNS 를 쓴다면 `./deploy.sh https ourcompany.duckdns.org 담당자@회사.com`)

이메일은 인증서 만료가 임박했을 때 Let's Encrypt 가 알려 줄 주소입니다. 생략해도 됩니다.

명령이 하는 일:

1. 도메인이 정말 이 서버를 가리키는지 확인합니다.
2. 서버 방화벽에 80 · 443 을 엽니다.
3. Nginx 설정을 만들고 서비스를 HTTPS 구성으로 다시 띄웁니다.
4. **바깥에서 80 번으로 들어올 수 있는지 먼저 확인합니다.**
   (막혀 있으면 인증서 발급을 시도하지 않고 멈춥니다. 발급 실패가 쌓이면
   같은 도메인으로 한 시간 동안 다시 받을 수 없기 때문입니다)
5. 무료 인증서를 받아 적용하고, 실제로 HTTPS 로 열리는지 확인합니다.

## 전환한 뒤에 달라지는 것

| | 전환 전 | 전환 후 |
| --- | --- | --- |
| 접속 주소 | `http://168.110.38.57:8000` | `https://itam.회사.co.kr` |
| 예전 주소로 들어오면 | — | 새 주소로 자동으로 넘어갑니다 |
| **이미 붙여 둔 QR 라벨** | — | **그대로 동작합니다** (새 주소로 넘어갑니다) |
| 로그인 | 유지 | **한 번은 다시 로그인**해야 합니다 |

라벨을 새로 인쇄하면 QR 에 새 주소가 들어갑니다. 급하지 않습니다 — 예전 라벨도
`http://<서버IP>:8000/a/<자산번호>` 를 그대로 받아 새 주소로 넘겨주도록 해 두었습니다.

> 로그인을 다시 해야 하는 이유: 세션 쿠키가 HTTPS 전용(`ITAM_HTTPS_ONLY=1`)으로 바뀌고,
> 주소(호스트)가 달라지면 브라우저가 기존 쿠키를 새 주소로 보내지 않기 때문입니다.

## 인증서 갱신은 신경 쓰지 않아도 됩니다

Let's Encrypt 인증서는 90일짜리입니다. `certbot` 컨테이너가 함께 떠서 **12시간마다
확인하고 만료가 가까우면 자동으로 갱신**합니다. Nginx 도 하루 두 번 설정을 다시 읽어
갱신된 인증서를 반영합니다. 사람이 할 일은 없습니다.

갱신이 잘 되고 있는지 확인하려면:

```bash
docker logs itam-certbot --tail 20
docker exec itam-certbot certbot certificates     # 남은 기간 보기
```

## 되돌리기

```bash
./deploy.sh https-off
```

`http://<서버IP>:8000` 로 돌아갑니다. 인증서는 지워지지 않아서,
나중에 `./deploy.sh https <도메인>` 을 다시 하면 그대로 쓰입니다.

## 사내 인증기관(사설 CA) 인증서를 직접 쓰려면

회사에 자체 CA 가 있다면 Let's Encrypt 없이도 됩니다.

```bash
cp deploy/nginx.conf.example deploy/nginx.conf
# deploy/nginx.conf 의 server_name 두 곳을 실제 도메인으로 바꾸고
# 인증서 파일을 아래 이름으로 넣습니다
#   deploy/certs/fullchain.pem
#   deploy/certs/privkey.pem

# .env 에 도메인을 적고 HTTPS 전용 쿠키를 켠 뒤
echo "ITAM_DOMAIN=itam.회사.co.kr" >> .env
sed -i 's/^ITAM_HTTPS_ONLY=.*/ITAM_HTTPS_ONLY=1/' .env
./deploy.sh start
```

## 자주 겪는 문제

| 증상 | 원인과 해결 |
| --- | --- |
| `도메인이 아직 어떤 IP 도 가리키지 않습니다` | DNS 가 퍼지는 데 몇 분 걸립니다. 잠시 뒤 다시 실행하세요. DuckDNS 라면 `./deploy.sh duckdns` 를 먼저 하세요. |
| `도메인이 다른 곳을 가리키고 있습니다` | A 레코드 값이 서버 공인 IP 와 다릅니다. `./deploy.sh doctor` 로 공인 IP 를 확인해 고치세요. |
| `바깥에서 80 번 포트로 들어올 수 없습니다` | 위 **2단계**(오라클 콘솔 수신 규칙)를 빠뜨린 경우입니다. 80 과 443 을 모두 열고 다시 실행하세요. |
| 인증서 발급이 반복해서 실패한다 | 같은 도메인으로 1시간에 5번까지만 시도할 수 있습니다. 설정을 점검한 뒤 `ITAM_LE_STAGING=1 ./deploy.sh https <도메인>` 으로 먼저 연습 발급(가짜 인증서)을 해보세요. |
| 브라우저에 "안전하지 않음" 이 뜬다 | 임시 인증서 상태로 멈춰 있는 경우입니다. `./deploy.sh https <도메인>` 을 다시 실행하세요. |
| 502 Bad Gateway | 앱 컨테이너가 다시 만들어진 뒤 Nginx 가 예전 주소를 보고 있는 경우입니다. `./deploy.sh restart` 로 해결됩니다. |
| 로그인해도 로그인 화면으로 돌아온다 | `ITAM_HTTPS_ONLY=1` 인데 `http://` 로 접속한 경우입니다. `https://` 주소로 들어가세요. |
| 엑셀 업로드 시 413 오류 | 파일이 `client_max_body_size` 보다 큽니다. `deploy/nginx.conf` 값과 `.env` 의 `ITAM_MAX_UPLOAD_BYTES` 를 함께 올리세요. |
